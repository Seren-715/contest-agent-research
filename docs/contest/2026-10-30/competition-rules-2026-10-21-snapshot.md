## 赛题一 · 科研助手

C类事实满分15：既有冻结事实逐项取0、0.6或1档，再以15乘平均档位。引文满分10，独立于事实分：合法性与正文/参考条目一致性3分、不同指定文献覆盖3分、反打包1分、跨段落均衡支撑1分、上下文与材料Metadata主题相关性2分。没有有效正文引用时全部为0；页码不影响分数。正文支持数字引用格式；Metadata相关性不代表已核验PDF原文支持。

引文规则：未知材料每篇扣1.5，僵尸/悬空/重复编号每处扣1，合法性最低0；覆盖为3乘实际引用的不同允许材料数占比。每组至少3个引用视为打包，占比0得1分、不超过30%得0.5分、否则0分。每篇被引材料至少出现两个实质段落且单篇实例占比不超过80%时均衡项1分，否则0.3；实质上下文最低12有效字符。上下文相关性取0/0.5/1，按所有实例均值乘2，未知来源为0。

E类满分15：八要点等权，档位0/0.3/0.7/1；15乘平均档位，再乘专属性系数high=1、medium=0.85、generic_template=0.55。缺明确基线与改进组比较、缺具体量化指标、技术方案有效内容不足200字符，每项扣1、最多扣3，最低0。参考文献、代码及重复句子不凑技术篇幅。正档位的要点/引用摘录须为相应原文，最多160字符。

C/E裁判引文先按原包进行格式匹配：精确匹配、空白/Markdown排版归一、省略拼接的连续片段及相似度至少0.75的有界匹配，最终回填报告原文真实切片并限制160字符。C引用只在指定引用上下文内查找。零档位允许空证据，缺字段、非法类型、非法档位或缺条目仍拒绝。

仅最后一次尝试允许从对应章节/关键词相关段落截取最多120字符保底；C引用仅取指定上下文。此举不改变裁判档位，也不证明摘录足以支持档位。保底记录manual_review_recommended，须供管理员抽查；无相关原文仍待补评。原始模型输出、匹配方法、位置、源哈希与重试诊断保留。此次修复不自动补评历史失败记录。

每道C/E题仍为一次逻辑裁判调用，格式错误最多额外2次校正。模型判断档位与依据，Python确定性算分；不新增后处理模型请求。裁判格式异常保留null和待补评，不冒充选手0分；合法的选手失败仍按原固定分母处理。质量策略版本和SHA-256绑定封存结果，禁止把旧策略局部补评与新版结果混算。

选手八字段输入、JSON/Markdown产物协议未改。原包参赛者文档保持原样；其中旧C/E二值公式以本版分档规则为准。Token真实用量仅独立展示，专家复核与综合成绩另行处理；未确认的专家/Token内部权重不擅自合成。

D01/D02/D05 均采用平台受控冻结脚本的真实运行观测和私有签名产物；checkpoint 分别为 6/6/7 个，流水线20分、数据12分、图表8分。Agent自报过程不作为通过证据；该观测不等同于完整OS系统调用审计。D01/D02性能项使用本服务器同镜像、同资源限额的三次实测中位数标定。本次D类技术发布为 challenge1-d-runtime-20261017-r1，原历史记录不重评；无正式排名资格的完整结果只显示联调分，正式排名开关保持关闭。题量11不代表已验证15分钟限时。

## 赛题三 · AgentCC

题库保留 48 个候选实例：4 个基础拓扑、3 种带宽配置、2 类算子、2 个难度。每次按“基础拓扑 × 算子 × 难度”分层抽取 16 例，每个分层从三种带宽配置中抽取 1 例。普通题 8 例，合计权重 40%；复杂题 8 例，合计权重 60%。单例按 100 分展示：正确性 10 分、通信性能 50 分、求解时间 40 分。无效、缺失或超时实例的三项分数均为 0。

通信性能采用固定双锚点分段对数规则。`T_i` 为官方 Judge Replay 耗时；`L_i` 为对该例拓扑扫描有向割集、加入至少一轮启动开销得到的可证明必要下界；`U_i` 为固定版本分层保守构造器生成的合法方案，经同一 Judge 重放所得可行上界。两者均逐例计算并与任务、拓扑、判题器及构造方案哈希一起冻结，不使用任何参赛者或参考 Agent 的成绩作转折点。令 `B_i=2U_i`，`M_i=U_i^(3/4)L_i^(1/4)`，通信分 `C_i`（最高 50）为：

```text
T_i >= B_i:           C_i = 0
M_i < T_i < B_i:      C_i = 40 * ln(B_i/T_i) / ln(B_i/M_i)
L_i < T_i <= M_i:     C_i = 40 + 10 * ln(M_i/T_i) / ln(M_i/L_i)
T_i <= L_i:           C_i = 50
```

`2`、`1/4` 及 `40+10` 是全实例统一、版本冻结的评分政策参数，不是理论定理。旧标定中的 `baseline_time_us` 和 `lower_bound_us` 仅供既有官方输入校验兼容，v19 实际计分只读取 `certified_lower_us` 和 `conservative_upper_us`。如出现有效方案 `T_i<L_i`，应复核下界证明和 Judge，而不能仅凭该事件宣称最优。

求解时间 `t_i` 从平台发出完整实例请求开始，到完整收到并解析最终 JSON 响应为止。容器启动、健康检查和响应收齐后的独立判题不计入；输入解析、模型调用、搜索、Replay 调用、内部校验和结果序列化均计入。

每个候选实例分别计算满分线。参考 Agent 在 1 CPU、1024 MB、256 pids 的限制下运行；每个样本都创建新容器，健康检查成功后调用一次 `/solve`，每例运行 20 次。20 个样本使用 nearest-rank P95，即排序后的第 19 个样本。P95 与该例已有正式有效耗时取较大值，乘 1.25，再向上取整到 50 ms：

```text
t_good_i = ceil(max(P95_i, historical_valid_i) × 1.25 / 50) × 50 ms
```

180000 ms 只作为硬超时线。有效实例的时间系数为：

```text
t_i ≤ t_good_i：q_i = 1
t_good_i < t_i < 180000：q_i = ((180000 - t_i) / (180000 - t_good_i))^3
t_i ≥ 180000：q_i = 0
```

求解时间分为 `40 × q_i`。标定文件保存全部原始样本、nearest-rank P95、历史有效耗时、1.25 余量、50 ms 取整值、参考镜像哈希、资源限制、任务与拓扑哈希、判题器哈希及 Replay 版本。

Token 只展示，不计分。历史运行继续使用各自冻结规则，不按 v19 重算。正式排名开关保持关闭。
