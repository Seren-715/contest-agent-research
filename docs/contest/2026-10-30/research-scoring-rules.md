# 赛题 1「科研助手」评分规则与打榜流程

云端时限（2026-10-24）：A/B 单题 540 秒，C/D/E 单题 900 秒，包含模型、工具及实验等待；D 平台执行 840 秒、RPC 870 秒、客户端 880 秒均包含在单题预算内。裁判模型单次请求最多 900 秒，仅对可纠正输出有界重试；整轮时长由实际题量和各阶段决定，不承诺 15 分钟完成。平台裁判或证据链故障保留原答卷、成绩为空，等待核查/补评。

本文件说明参赛提交、自动判题、人工复核和榜单发布流程。路径以联调包根目录为起点；五类输出的完整字段定义见同目录 `Agent输入输出格式规范.md`。平台上传接口、参赛模型清单、资源配额和榜单发布时间由赛前公告确定。

本文件仅面向参赛者。平台负责派题、自动判题和专家录分；参赛者负责读取本轮题目、生成结果并提交。输入输出字段以 [Agent输入输出格式规范.md](Agent输入输出格式规范.md) 为准。

## 一、Agent核心功能要求

参赛开发的科研智能体应面向论文库中的科研任务，支持用户通过自然语言逐步完成文献整理、问题分析和研究方案构建，并确保关键结论有据可查、过程可追溯。

1. 论文入库与一键整理：支持将 PDF 论文批量导入，自动提取标题、作者、摘要、关键词、发表年份、引用信息及正文内容；根据研究主题、方法、任务、数据集等维度生成标签和分类，建立可检索的论文索引，并提供导入状态、解析结果和异常文件提示。

2. 论文检索与推荐：支持用户以自然语言描述研究主题、技术方向或具体问题，在论文库中进行语义检索；根据主题相关性、发表时间、论文内容和可用引用信息排序，返回相关论文及推荐理由。检索结果应能区分高度相关、部分相关和低相关文献，减少无关结果，并支持围绕检索结果继续追问和筛选。

3. 论文分析与实验复现：支持从论文中提取研究问题、核心方法、实验设置、数据集、评价指标和主要结论；对于提供了代码或实验环境的论文，能够在受控环境中解析项目结构、配置依赖、执行可行的实验流程，并记录运行日志、环境信息和结果。智能体应对复现中遇到的问题及论文报告结果与实际结果之间的差异进行分析，避免将未执行或未验证的结果表述为已复现结论。

4. 文献证据整理与综述生成：支持围绕用户指定主题检索和筛选多篇论文，提取研究方法、数据集、指标、结论及局限，形成结构化文献证据矩阵；在此基础上梳理研究脉络、方法类别、观点差异和发展趋势，生成结构清晰的综述报告。综述中的事实、数字和引用应能追溯到具体论文及相应内容，避免虚构文献、错误归因或缺少依据的结论。

5. 研究问题与 Idea 升华：支持通过多轮交互澄清用户的初步想法，并结合论文证据和可获得的复现结果，识别已有方法的局限、不同研究路线的互补关系及值得探索的问题。

6. 文档读取、定位与写入（必备）：能够解析 JSON、Markdown、文本和允许的 PDF，按本队派题记录定位 11 道题，检索完整文件名与正文证据，在本队授权目录写入结果并回读校验。材料缺失或写入失败须如实反馈，不得访问其他队伍或平台内部资料。具体接入验收见输入输出规范。

## 二、五类题型、11 套案例与七个评分项

版本：`research-assistant-objective-v3`。五类题型为 Chat、Literature_Retrieval、Survey、Reproduction、Idea。按 1-3-2-3-2 分配独立测试案例，总计 11 套，不以同题重复运行代替。

| 评分项    | 满分   | 对应题型                     |
| ------ | ----:| ------------------------ |
| 聊天类    | 5 分  | A / Chat                 |
| 检索类    | 15 分 | B / Literature_Retrieval |
| 综述事实类  | 15 分 | C / Survey               |
| 引文溯源类  | 10 分 | C / Survey               |
| 要点覆盖类  | 15 分 | E / Idea                 |
| 实验流水线类 | 20 分 | D / Reproduction         |
| 数据与图表类 | 20 分 | D / Reproduction         |

七个评分项满分合计 100 分。

自动打榜成绩满分 100 分，只由客观判题产生，占最终综合成绩的 70%。专家评分与 Token 消耗评分独立复核，合计占最终综合成绩的 30%，不参与初赛自动排行榜。复核内部权重目前留空，待负责人确认；不能默认两项各占 15%。

按 1-3-2-3-2 分配独立测试案例，总计 11 套。每题先按其适用评分项计分，再计算类别平均：`S_i = sum(s_ij) / N_i，N_A/N_B/N_C/N_D/N_E = 1/3/2/3/2`。例如 B 类三题得分为 10、12、14 时，平均分为 12。A/B/C/D/E 类单题及类别平均上限分别为 5、15、25、40、15 分，自动打榜成绩为五类平均分之和，等价于七个评分项在适用类别内的平均分之和，不再归一化。

最终综合成绩为 `0.7 × 自动打榜成绩 + 0.3 × 复核部分折算成绩`，两部分均以 0～100 分计。例如 80 与 90 合成为 83。复核结果不覆盖客观原始分或自动榜分；复核未完成或内部权重未确认时，综合成绩为 `null`。

每套案例保留原始证据分、映射后的单题分、运行状态及错误。选手答题失败、超时或非法输出按本题规则计分；裁判模型、平台实验服务或证据归档失败不判为选手 0 分，本轮暂不生成完整成绩，保留原产物等待核查或补评。D 类v3依据可信执行证据独立计分；D-05实际完成的条件可保留部分分，总指标不可核验仍为null。尚未返回结果且未收到终止状态的案例为 `pending` / `running`，不得忽略它或用已完成案例平均生成完整榜分。派题身份、题目哈希或额外结果文件异常会阻止本轮进入榜单。

## 三、打榜流程

### 3.1 流程总览与职责

一轮打榜依次经历：公开用例调试 → 上传 Agent 镜像 → 平台登记版本并随机派题 → Agent 读取 11 道题并作答 → 本队产物提交 → 客观判题与初赛自动榜分 → 独立复核 → 条件满足后综合成绩 → 反馈与申诉。

| 环节    | 参赛者负责                             | 平台负责                    |
| ----- | --------------------------------- | ----------------------- |
| 准备    | 实现五类任务及文档能力，打包镜像，验证输出             | 公布接口、公开调试材料、资源配额和规则版本   |
| 执行    | 定位本轮题目，读取允许材料，运行实验并写入本队产物         | 随机派题、提供隔离环境与模型接口、记录运行过程 |
| 提交    | 交付11 个结果 JSON、Markdown、图片及要求的实验产物 | 收集并冻结提交版本，校验文件后评分       |
| 复核与排名 | 提供创新功能证据，查看本队反馈                   | 专家评审、完整成绩汇总、榜单发布及争议处理   |

### 3.2 公开调试材料与预检查

平台发布公开用例和格式示例，公开调试成绩不计入正式榜单。示例中的数值、引用和报告仅说明格式，不能直接充当正式答案。平台只向 Agent 提供本轮派题记录、11 道题和允许材料。

提交前在参赛工作区根目录执行，将“你的队伍名”替换为本队目录名：

```powershell
py -3 参赛者模拟\validate_submission.py 你的队伍名
```

预检查检查派题和结果文件、部分字段及 Markdown 一致性，不验证论文事实、实验真实性或全部 Schema 约束。D 类未完成时仍应使用 `failed` 或 `materials_missing`，不能为使预检查通过而伪造成功。

### 3.3 镜像上传与版本登记

按平台镜像规范提交 Agent 镜像及启动说明；入口、架构、服务端口、健康检查和模型接口以平台接入公告为准。镜像应包含文档解析、检索、文件写入与实验运行所需依赖，不能假设执行时可临时访问外网安装工具。

平台登记提交版本并关联 `submission_id`。重新上传形成新版本，已登记版本用于对应轮次评测，不得在评测过程中替换程序或结果文件。上传次数、截止时间和重提交规则以公告为准。

### 3.4 运行环境与目录权限

平台提供本队隔离工作区、只读题目和允许的论文材料；Agent 使用统一模型接口及本轮公开的资源配额。模型、Token 限额、时间片和超时条件以冻结接口公告为准。

Agent 可以读取本队 `dispatch.json`、`assigned/`、允许材料及本队产物；可以写入本队结果和工作文件、本队图片，以及按命名规则划分的本队 Markdown 报告。原始题库、参考答案、内部评分资料、裁判凭据和其他队伍文件均不在授权范围内。题目与派题记录只读，路径须保持在授权范围。

当前 D 类采用单机低资源离线协议，CPU 可执行，不要求多 GPU 集群或真实网络管理权限。逐题指标的精确名称、单位、运行环境和提交要求直接读取本题 `input`，无需另读指标说明文档；数据与冻结脚本使用本题允许材料。

### 3.5 随机派题与输入定位

每次派题含 A、B、C、D、E 分别 1、3、2、3、2 套独立案例。正式A/B/C/D/E 分别 1/3/2/3/2 个不同案例，一轮共 11 个题号。旧版各一题模式只供调试，不产生新版完整榜分。

```text
data/<队伍名>/dispatch.json
data/<队伍名>/assigned/A-xx.json
data/<队伍名>/assigned/B-xx.json
data/<队伍名>/assigned/C-xx.json
data/<队伍名>/assigned/D-xx.json
data/<队伍名>/assigned/E-xx.json
```

Agent 先读取 `dispatch.json` 的 `case_ids`，再按 `cases[].question_file` 定位题目。不得自行抽题、扫描未派题目或把输入 JSON 复制为答案。定位文件后仍须核对题目内部 `case_id`，每道题独立按 `output_schema_ref` 执行。

| 类别                       | Agent 执行动作        | 必交结果字段                                         |
| ------------------------ | ----------------- | ---------------------------------------------- |
| A / Chat                 | 回答科研问题，提出一个关键澄清问题 | `case_id`、`answer`、`clarifying_question`       |
| B / Literature_Retrieval | 检索允许论文库、核验正文并去重   | `case_id`、`papers`，每篇含完整 `filename` 和 `reason` |
| C / Survey               | 比较指定论文，整理事实及引用    | `case_id`、`path`、完整 `markdown`，另存同文 Markdown   |
| D / Reproduction         | 核验环境与材料，执行实验并生成图表 | `case_id`、`status`、恰好三项 `metrics`、`figures`    |
| E / Idea                 | 根据论文和模拟观察提出可验证方案  | `case_id`、`path`、完整 `markdown`，另存同文 Markdown   |

### 3.6 文件写入与提交

11 个 UTF-8 JSON 写入队伍目录根部，文件名和内部 `case_id` 必须与派题记录一致。以下仅列每类一个文件，实际按派题记录写入全部 11 个 JSON：

```text
data/<队伍名>/A-01.json
data/<队伍名>/B-02.json
data/<队伍名>/C-03.json
data/<队伍名>/D-04.json
data/<队伍名>/E-05.json
data/expert/C-03-综述-<队伍名>.md
data/expert/E-05-灵感Idea报告-<队伍名>.md
data/figure/<队伍名>/D-04-result.png
```

Survey/Idea 正文至少 800 个字符，含 `## 参考文献`，JSON 正文与另存 Markdown 逐字一致。Survey 文件名严格为 `case_id-综述-队伍名.md`；Idea 文件名符合 `case_id-*Idea报告-*队伍名.md`。

D 类图片必须实际存在，每张图包含 `caption`、`x_label`、`y_label`、`legend`。本队实验代码、缓存和中间产物放入本队工作子目录（例如 data/<队伍名>/work/），保留平台要求的真实运行产物。写入后重新读取校验，再按平台接口提交或确认作答结束。

输出只含当前题型字段，不添加输入题目的 `function`、`title` 等字段，不添加自然语言前缀或 Markdown 代码围栏。创新功能的实现证据按平台要求单独提交，不改变五类 JSON 结构。

### 3.7 D 类实际运行要求

只有实际执行且结果可追溯时才使用 `completed`。材料缺失用 `materials_missing`，运行失败用 `failed`；无法核验的指标值用 `null`，不从论文、示例或参考值推测 `observed`。

平台根据实际运行过程核验复现流水线和实验产物。参赛者按题目要求保留命令输出、实验数据和图表，不编造成功日志，也不修改平台采集记录。论文报告值、平台公开基线值与本次实测结果须分别注明来源。

### 3.8 自动评分与本队反馈

平台收集本轮结果并进行评分，参赛者通过平台查看本队分类得分、错误原因和复核状态。参赛者无需配置裁判服务或运行评分程序。

| 反馈状态                              | 含义                               | 后续动作              |
| --------------------------------- | -------------------------------- | ----------------- |
| `valid`                           | 11 案例终止结果齐全，自动榜分可计算，失败案例以 0 计入   | 查看逐题及类别平均分        |
| `incomplete`                      | 尚有 pending/running 案例，自动榜分为 null | 等待终止结果或补交         |
| `invalid` / `invalid_submission`  | 派题身份、题目摘要、额外文件等校验失败              | 修正范围或申诉           |
| 复核 `pending` / `awaiting_weights` | 独立复核未全或权重留空                      | 自动榜分保持；综合成绩为 null |

选手答题失败、超时或非法输出按本题规则计分并保留具体状态；平台判题、实验服务或证据链异常显示“待核查/待补评”，成绩为空，不混同选手 0 分或尚未评测。

### 3.9 专家评审

专家评审总分 100 分，按 Survey 深度、Idea 可行性、创新扩展、Token 四个维度,占比 30% 进行综合评定。人工分由专家填写，参赛者提交报告与必要说明，不提交专家评分文件。

### 3.10 完整成绩、榜单与多次提交

初赛自动排行榜只使用客观自动榜分，满分 100 分。最终综合成绩单独计算，采用 70% 自动成绩 + 30% 复核折算成绩。专家与 Token 的复核内部权重留空；未确认或未评完时不生成综合成绩。

多次提交保留各版本，同一案例和同一自动快照的专家重评不累加。每队采用最新或最好版本，以及同分处理规则，待平台公告冻结。公开调试成绩不作为正式排名。

### 3.11 反馈、申诉与赛后审查

平台反馈本队分类分数、复核状态、格式问题和运行失败原因。对平台异常或评分争议，按公告时限提交 `submission_id`、相关题号或报告项及问题说明，等待平台处理结果。

组委会按公告复核代码、镜像和运行记录。禁止硬编码正式答案、预置答案报告、伪造实验、访问内部评分材料或其他队伍文件、绕过统一模型接口。合法开源依赖应注明来源；违规处理依据赛事规则和实际证据执行。

## 四、评分规则

### 客观计分依据

1. **聊天类（5 分）**：合法 JSON 中 `answer` 得 3 分，`clarifying_question` 得 2 分，沿用现有字段检查。
2. **检索类（15 分）**：去重后令 H 为命中的相关论文数，N 为冻结相关论文数，U 为未命中冻结相关集合的论文数，`max(0, min(15, 15H/N - 0.75U))`。文件名仅字母大小写不同时按同一篇论文匹配和去重；其他字符须与完整文件名一致。重复论文不重复加分。
3. **综述事实类（15 分）**：冻结 K 项事实，C 为正确覆盖数，F 为严重事实错误数，`max(0, min(15, 15C/K - 3F))`。沿用冻结事实与逐项证据判定。
4. **引文溯源类（10 分）**：按题目给定的五份指定材料计算引用覆盖率。每份材料须在正文中有引用标记，且文末参考文献条目能对应到该材料；同一材料重复引用只计一次，仅列在文末而正文未引用不计。得分为 `10 × V / 5`，V 为有效覆盖的指定材料数量。页码可有可无，不核验页码真实性、原文页级内容或观点支持关系；页码有无不影响本项分数。事实准确性由综述事实类独立评分。
5. **要点覆盖类（15 分）**：研究动机、技术路线、实验设计、基准数据集、量化评价指标各 1.5 分；复现瓶颈反思、多文献互补机制各 3 分；场景可行性与落地约束 1.5 分。未覆盖项不加分，保留判定证据。
6. **实验流水线类（20 分）**：D-01/D-02/D-05使用layered-d-v3的实际输入、基线、候选、产物、条件覆盖、复跑与边界七类分项，按D类实验要求计分，不使用旧8个等权检查点。
7. **数据与图表类（20 分）**：D-01/D-02/D-05按可核验指标6、实验效果10、真实图表4计分；具体数学口径及部分分见D类数据与图表判分规则.md。

D 类底层保留原有 10 分证据量表，服务器适配器映射到上述 20 分上限，每项只映射一次。各项最低 0 分，最高为表列满分；不适用于本题的项不加分。

### 独立复核
