## 一、源码确认

### B
1. 模型调用前的整题失败点：`b_retrieval.py:148`（材料解析抛 `MaterialResolutionError`）、`:159`（无可识别 PDF）、`:170`（无可提取文本）。第 247 行是所有批次重排都失败。
2. 无正文的论文被静默剔除：`index_materials` 在字节上限、索引预算耗尽、解析失败时返回空文本记录（`paperlib.py:354-400`），`b_retrieval.py:166` 随后丢弃。这些论文即使是金标也不可能被返回。
3. 索引预算按路径顺序消耗：`CONTEST_INDEX_SECONDS` 默认 120 秒，且受 `deadline.remaining()-30` 限制（`paperlib.py:349-354`）。超时后排在后面的文件以 `index_budget_exhausted` 记录且无文本。路径按 `sorted` 字母序（`paperlib.py:90`），所以靠后的文件最先被牺牲。是否触发取决于论文库大小，**库大小未知**。
4. 中文查询的关键词扩展失败时静默返回 `[]`（`:95-97`），无日志，随后用中文查询对英文语料做 BM25。
5. 所有候选取前 80 篇（`:177-178`）。分数全 0 时排序退化为文件名字母序（`:135-138`）。
6. 提示词偏保守：要求至少覆盖两个具体要素，且强调误报扣分（`:188-195`）。按公式，N=5 时命中收益 3 分、误报代价 0.75。
7. 我们的文件名校验区分大小写（`:238`），平台不区分；模型只改大小写时会被我们丢弃。影响较小。

### C
1. 本地审计只检查形式：引用编号范围、参考文献映射、逐篇被引用、事实句带 `[n]`（`evidence.py:160-294`）。不判断句子是否被原文支持。通过审计不等于事实正确。
2. 证据矩阵默认关闭（`c_survey.py:51`）。默认路径：基础摘录每篇 `min(1800, 9000//篇数)`（`:59`）+ 补充矩阵。
3. 矩阵每篇每个维度最多取 2 个窗口，每个窗口长度 `min(1200, quote_budget//窗口数)`（`reporting.py:120-143`）。窗口多时每个只有几百字符（推算：10 篇时每篇约 3400 字符、最多 12 个窗口，单窗口约 150-280 字符，**未实测**）。
4. 提示词要求具体数值同时核对方法/数据集/单位/指标/条件（`c_survey.py:74-78`），并要求对比表内事实也引用（`:85-86`）。窗口过短时，这些条件常不在同一窗口里。
5. 只有一次生成 + 最多一次修复；修复仅在存在结构 blocker 且剩余时间 ≥30 秒时触发（`:105`）。没有语义核对步骤。
6. 描述性材料范围只取 BM25 前 80 篇，每篇 750 字符摘录让模型选（`materials.py:53,65`）。
