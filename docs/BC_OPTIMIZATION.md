# B/C 证据与检索优化（2026-10-30）

## 实施范围

按方案审查修订后实施，不引入BGE/FAISS/torch，不更改D源码生成与正式执行流程，不增加付费模型调用验证。

- 材料：只解析声明的材料；显式缺失、同名歧义、越界和`..`路径明确报错，不改用整个论文库。仅B在未指定材料时允许发现论文库。缓存不跨题复用。
- 解析：B/C取消前20文件/前6材料、固定头尾选页限制，默认遍历全部授权文件与预算内页；保存SHA-256、PDF物理页码及该页pypdf原始提取字符串跨度。页段1200字符、重叠200。中文词项增加双字片段匹配。
- B：文档/页段BM25排名按论文去重后融合，分批模型筛选；最终结果不再固定5篇。明确空结果不回填，模型失败仅保留已筛选批次，不凭词项重叠补答；空正文文件不进入候选。
- C：逐篇公平分配六维候选原文矩阵，兼顾研究问题、方法、数据条件、指标、结果比较、局限；保留哈希与页内位置。仍为一次生成、最多一次带原草稿修复；较多结构阻断项的修订不覆盖原稿。没有新增语义审核硬门禁。
- E：生成与审核流程未改；共享索引的文本预算/分词/摘录实现有更新。默认bundle显式保留前8＋后4选页与48000字符上限，并有兼容测试。
- Survey失败兜底取消前6篇限制，不使用无正文文件拼接占位报告；超出正文限制仍拒绝发布。

矩阵中的“候选维度”是检索组织标签，不是已验证事实抽取结果。相同数值、引用编号有效或原文可定位，都不单独证明句子受到来源支持。

## 预算配置

以下为工程上限，不是官方建议值。达到上限会产生日志或矩阵解析限制提示；不把未处理内容当成已覆盖。

| 环境变量 | 默认值 | 含义 |
| --- | ---: | --- |
| CONTEST_PDF_MAX_BYTES | 67108864 | 单PDF最大字节数 |
| CONTEST_PDF_MAX_PAGES | 256 | 单PDF最大解析页数；超过后分散采样并报告 |
| CONTEST_PDF_MAX_CHARS | 256000 | 单PDF提取字符预算，公平分配给选中页 |
| CONTEST_INDEX_MAX_CHARS | 8000000 | 本次索引累计字符预算 |
| CONTEST_INDEX_SECONDS | 120 | 索引阶段协作式时间预算 |
| CONTEST_B_CANDIDATES | 128 | B最多送入模型的候选论文数 |
| CONTEST_B_BATCH_SIZE | 16 | B每批候选数 |
| CONTEST_B_BATCHES | 8 | B最多批数 |
| CONTEST_B_RESULTS | 80 | B最多返回数；无需凑满 |
| CONTEST_B_EXCERPT_CHARS | 1400 | B每篇提示中的证据字符预算 |

C证据矩阵总预算36000字符，每篇最多6000；无法为每篇保留有效原文时明确失败。B/C共享单题Deadline，模型请求按剩余时间收缩；解析为后续模型留30秒，外层执行控制下为收尾留15秒。页间检查不能中断单次pypdf内部解码，因此不是独立解析进程的硬超时/内存隔离。仅扫描PDF不会解决OCR扫描件，无可提取文本会显式提示。

## 离线评估

独立人工标注、完整相关集合和留出测试集仍需建立。不要将开发测试夹具当成隐藏题成绩或训练/测试独立的评测集。

```powershell
uv run --offline python scripts/evaluate_retrieval.py --gold gold-b.json --predictions answers-b.json
uv run --offline python scripts/evaluate_survey.py --gold gold-c.json --annotations annotations-c.json
```

B gold为`[{"case_id":"B-01","relevant":["a.pdf","b.pdf"]}]`；predictions为标准B答卷列表。输出H/N/U、论文级召回、precision、去重后Recall@k及公式`max(0,min(15,15H/N-.75U))`。这是所提供gold上的公式分，不是平台成绩；未标注返回项按U处理，因此gold必须完整。

C输入示例格式见`evaluate_survey.py`模块说明。人工核验covered_fact_ids、severe_error_ids及每条claim的supported=true/false/null；输出核心事实召回、按论文/主题分解、正文事实支持比例、未知比例的原始计数，以及`max(0,min(15,15C/K-3F))`在所提供gold上的分数。未知不自动标成严重错误；该工具不复现官方10分引文评分，也不自动判定语义蕴含。

## 验证与边界

本轮Python3.9.25与3.11.15均182 passed、3 skipped；跳过为缺D参考实现的1项与缺本地真实响应文件的2项。测试包括22个PDF中的最后一份第10/24页唯一证据、超过5篇结果、多批去重与失败保留、指定材料缺失/歧义/越界、中间页/页内跨度、原文矩阵结果及局限、修复草稿和预算、官方公式及事实准确率与召回区别。

官方基础镜像内Python3.11.16、UID1000、`--network none`联调，模型由容器内本地HTTP桩代替：B/C的`POST /solve`均200，B返回8篇，C报告与JSON/文件逐字一致。初次联调发现真实`ModelClient.complete`不支持B传入的timeout参数，已补齐接口、透传及真实客户端方法回归；修复后联调通过。联调只验证协议及运行链路，不评价模型答案质量。

排除条件测试验证条件进入提示且明确空结果不被回填；尚未证明真实模型对复杂排除条件的判定效果。没有平台B/C原题、完整论文及裁判细节，也没有本轮在线模型或平台复测，不声明真实提分、事实召回达标或正式排名就绪。

## 2026-11-01 B 两阶段检索

B 论文库约100多篇。按本地实测单次调用16～37秒估算，原流程（关键词扩展 + 最多120秒索引 + 8批×16篇串行复核）可能超过540秒，后面的批次被截断，而这些批次由BM25排序决定，可能包含金标论文。

- 论文数超过`CONTEST_B_SCREEN_THRESHOLD`（默认40）时，先做宽松初筛：每批`CONTEST_B_SCREEN_BATCH`（默认70）篇，每篇只给标题与约`CONTEST_B_SCREEN_CHARS`（默认500）字符原文，每篇论文恰好被模型看一次；拿不准时保留。
- 初筛留下的论文按原排序进入带1400字符证据的严格复核，复核规则、reason要求与输出不变。
- 某个初筛批次失败时，该批论文全部放行到复核；所有初筛批次都失败时退回原流程；初筛成功但全部排除时返回空结果。
- 130篇时调用次数约为：扩展1 + 初筛2 + 复核1～2，原流程约为1 + 8。实际耗时未经平台验证。
